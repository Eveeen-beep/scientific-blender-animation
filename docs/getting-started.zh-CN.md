# 从下载到第一张科研检查图

不需要先学编程。你可以用文件管理器安装技能，再把下面的提示词交给 agent 执行；需要你提供的是项目文件夹、科研材料和本轮想得到的结果。

[下载完整 ZIP](https://github.com/Eveeen-beep/scientific-blender-animation/archive/refs/heads/main.zip) · [仓库首页](../README.md) · [平台与验证范围](compatibility.zh-CN.md)

## 1. 下载后，选你正在使用的平台

在仓库首页点击 **Code → Download ZIP**，也可使用上方下载链接。解压后找到直接包含 `SKILL.md` 的文件夹，按对应安装页复制**完整文件夹**：

| 你使用的产品 | 接下来打开 |
|---|---|
| Codex | [Codex 安装与调用](install-codex.zh-CN.md) |
| Claude Code | [Claude Code 安装与调用](install-claude-code.zh-CN.md) |
| Cursor | [Cursor 安装与调用](install-cursor.zh-CN.md) |

确认最终目录是 `scientific-blender-animation/SKILL.md`，旁边保留 `references/`、`assets/`、`scripts/` 与 `agents/`。避免解压后多套一层目录，也不要只复制入口文件。

Claude Code 和 Cursor 的安装路线已核对官方文档，**本仓库尚未在其产品内实测安装、触发、连接 Blender 或渲染**。先完成下面的自检，再判断你的环境是否可用。Codex 有历史项目实践，本次 v1.2 的检查范围见[兼容性说明](compatibility.zh-CN.md)。

## 2. 准备一个项目文件夹

选择一个你能找到的空文件夹作为本次输出目录。把设备图、示意草图、工艺说明或已有 `.blend` 放进去；没有现成模型也可以先做新场景。记下该文件夹的完整路径，后续提示词中的方括号内容由你替换。

需要准备的环境是：能读写项目文件和运行命令的 agent，以及一条真正可用的 Blender 执行通路（Blender 自带 Python / 命令行，或已配置的连接器 / MCP）。PNG 序列审核需要普通 Python 与 Pillow；FFmpeg 按视频任务选用。技能包本身不包含 Blender、产品账号或 API 账号、研究数据与模型素材。

不清楚软件装在哪里也可以让 agent 先检查。若当前产品只有聊天能力、没有本地文件或命令工具，需要先使用具备相应工具的环境。

## 3. 先发“只读环境检查”

先按安装页调用技能：Codex 使用 `$scientific-blender-animation`，Claude Code 使用 `/scientific-blender-animation`，Cursor 在 Agent 聊天输入 `/` 后选择技能。随后发送：

```text
请使用 scientific-blender-animation 技能，先做环境与工程只读检查。

项目文件夹：[填写完整路径]
已有工程：[填写 .blend 完整路径；没有就写“新建，尚无工程”]

请读取技能说明，确认可用文件工具、命令执行方式和 Blender 执行通路。
查找 Blender 实际路径与版本；不要扫描整个系统盘。
已有工程请读取磁盘版本的 Scene、Camera、当前帧、帧范围、帧率、单位与对象摘要；
新建任务请明确使用的空白场景与未保存状态。
如果界面有未保存修改，请先说明它与磁盘版本的区别。

本轮不改 .blend、不建模、不渲染、不安装软件。
允许在项目 reports 文件夹写一份新的自检报告；已有报告不要覆盖。
列出检查通过项、缺失项、实际错误与最短下一步，然后停止。
```

这一步的结果应包含真实路径、版本和场景摘要。只有“已连接”“发现进程”或“命令已生成”还不够。报告缺少执行工具时，先按错误解决环境问题，不要要求 agent 直接继续制作。

## 4. 用一个小任务得到第一组检查图

环境检查通过后，再做一个代表过程。下面是可直接改写的入门例子；你有自己的研究材料时，替换“过程”一段，并附上图和参数。

```text
请使用 scientific-blender-animation 技能，在这个项目中制作一个科研工艺示意小样。
项目文件夹：[填写完整路径]

过程：固定喷嘴向水平基板供给材料，基板平移，材料在后方形成一条沉积带。
观众：第一次了解这个过程的同学。
本轮目标：先让人看懂“供给→接触→沉积”的关系，输出起始、作用中、结束三张检查图。

这是概念示意，不是流体或凝固数值仿真。
请先说明因果链、谁运动、单位和允许简化；缺少依据的尺寸与速度标为演示值。
使用最少必要对象，先做好接触位置与相对运动。
完成基础场景，保存可编辑 .blend 和实际执行脚本，另附检查结果。
不要启动完整动画渲染。完成三张图并更新 PROJECT_HANDOFF.md 后停止。
```

三张图适合检查结构、方向、接触和构图，不能证明整个动画连续正确。看图后用具体描述修改，例如“喷嘴应固定，基板向右移动”“沉积带应接触基板”，并说明哪些部分保留。

若你已经有工程，改用下一节的恢复入口，避免新场景构建覆盖已有工作。

## 5. 有工程或中断记录，就从现状继续

```text
请使用 scientific-blender-animation 技能，恢复已有项目。
项目文件夹：[填写完整路径]
已知工程：[填写 .blend 完整路径；不确定就说明]
交接记录：[填写 PROJECT_HANDOFF.md 或原有 CODEX_HANDOFF.md 的路径]

请先只读核对真实文件、最近日志、已有输出和活动 Blender / 渲染任务。
不要仅凭文件名版本号选择基线；交接记录与磁盘不一致时，以实际证据定位差异。
列出已实现、已保存、已审核和未完成的内容，给出可靠续作点。
本轮只完成：[填写具体修改或恢复目标]
保留：[填写需要锁定的几何、运动、镜头等]
停止点：[例如“完成同帧对比图后停止”]

另存有说明的新版本；不重跑已成功的构建，不重复启动活动渲染。
已有渲染帧先核对来源与完整性，再决定是否补帧。
更新现有交接记录并报告实际完成范围。
```

新项目默认使用 `PROJECT_HANDOFF.md`。旧项目已有 `CODEX_HANDOFF.md` 就沿用，并在换 agent 时提供该路径。交接记录帮助找回进度，恢复时仍要核对磁盘和活动任务。

## 6. 逐步增加输出，并保留停止点

推荐顺序是：**结构检查图 → 一个代表过程 → 覆盖关键转折的短动态 → 完整帧序列与视频 → 归档**。每一步都可以用自然语言指定范围，不必一次要求长片。

| 你要做的事 | 可以直接发送的补充要求 |
|---|---|
| 看完检查图再决定 | “完成指定检查图、保存工程和交接记录后停止，等我看图。” |
| 检查连续运动 | “制作覆盖供给、接触和停止转折的短预览，说明实际检查的时间范围。” |
| 已确认方案，继续制作 | “方案与范围已确认，检查通过后按约定继续到最终输出；遇到未定科学参数再提出。” |
| 中断后继续 | “先核对已有文件和活动进程，只补未完成部分，并沿用现有交接记录。” |

完整输出前要分别检查科学含义、几何与运动、静帧、连续动态和文件完整性。PNG 能解码不代表画面已验收；来源不明的旧帧也不能直接并入新视频。具体工序由技能按任务裁剪，停止点以你本轮的要求为准。

## 遇到问题时怎样反馈

先把 agent 的原始错误和自检结果保存下来，再向仓库提交 Issue 或交给接手者。可以复制下面的格式：

```text
使用平台与版本：Codex / Claude Code / Cursor，版本：
操作系统：
技能版本或下载日期：
Blender 完整版本与执行方式：CLI / bpy / 连接器或 MCP
本轮目标：
复现步骤：
期望结果：
实际结果与原始错误：
最后成功步骤：
已生成的工程、报告、日志与交接文件：
是否仍有活动渲染或未保存修改：
最小示例或截图（如有）：
```

公开反馈前移除私人路径、账号密钥、未公开研究数据和无权分发的素材。缺少哪项工具就报告哪项；普通 Python 没有 `bpy`、宿主不能执行命令、Blender 无法读取工程是不同问题，不要直接把它们归为“工程坏了”。
