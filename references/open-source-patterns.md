# 从开源项目提炼的可复用方法

在需要数据导入、程序化复杂几何或生产自动化时读本文件。项目证据与版本边界见[选型表](open-source-selection.md)。以下是为本工作流归纳的方法，不是复制上游代码，也不要求同时安装这些插件。

## 1. 先数据，后几何，最后样式

借鉴 MolecularNodes 的属性与显示分离、BVTKNodes 的 reader/filter/mapper、BlenderProc/BlenderSynth 的分阶段接口：

```text
输入数据及出处 → 单位/坐标/时间适配 → 原生几何与命名属性
                                    ↓
                        工艺/物理状态 → 主画面、小框、标签
                                    ↓
                        样式与相机 → 渲染 → 审核
```

只有相关层变化时才重算该层；不得为了换文字或配色重导入数据、重建场景。新建时可分模块，续作时只补必要适配层。

导入科学数据前记录：
- 输入格式、数据集/帧身份、长度/时间单位、轴方向、原点和显示放大比例；
- 字段是标量/向量/类别，定义在点、单元还是面上；无效值和插值方式；
- 源时间到展示时间的映射、稳定实体 ID、周期边界/拓扑变化；
- 哪些值来自实验/求解，哪些仅为样式或示意。

先核对少量已知坐标、一个已知距离、一个时刻和一个字段范围，再导全量。换插件大版本时重查尺度转换；漂亮的模型不证明单位正确。标量色标跨帧固定范围，除非明确注明逐帧归一化。不要将伪造向量场或材质噪声当成测量/求解结果。
使用中间格式时核对它实际保留了哪些字段、实体ID和时间信息；导出一个可看的mesh不等于保留了温度/向量/时序。必要的属性和映射元数据应随缓存交付，不能默认普通网格格式完整保真。

按核验需要把 beauty 图与深度、法线、对象/文字ID或AOV等诊断输出分开。诊断通道用于找遮挡、识别语言差异范围或检查数据映射，不默认新增所有通道。数值数据保留合适位深与未套显示变换的值；图像语言mask仅覆盖实际文字，不掩盖小框内的机理差异。

## 2. 把反复修改的机构做成有接口的模块

借鉴 Sverchok、Tissue 和原生 Geometry Nodes：让轨迹、截面、执行器、接触区、示意粒子各有小接口，而不是一份脚本包办整个工程。

接口至少明确：输入单位/坐标、参考对象或面、参数范围、输出对象/属性名、依赖和随机种子。可用 node group / Collection / 小型 bpy 函数，不要求全部改成节点。

例如轨迹模块可输出 `position(s)`、切向和法向；执行器用同一弧长参数求后置位置，截面与状态也读取它。直线、圆环和用户曲线只是轨迹实现，不复制三套工艺状态机。复杂三维曲线要检查局部坐标架连续，避免法向翻转。

重复单元优先实例化；只有导出、布尔、接触检查等确实需要时再实体化。Tissue 的面映射适合蜂窝/晶格/多孔构件，但要查单元翻转、畸变、自交和壁厚；生成规则不是材料性能证明。

在恢复任务中，“参数化”不等于重新运行整场构建。补丁检查源身份与对象存在性，记录改动集合和成功标记，已经应用过就停止或只补未完成项。

## 3. 渲染状态必须能重现

借鉴 Animation Nodes 的可复用子程序、MolecularNodes 的轨迹读取与原生 GN 缓存：
- 无历史依赖的示意用 `state = f(time, seed, parameters)`；同一帧不受访问顺序影响。
- 有历史依赖的模拟先求解/缓存，再供显示与渲染读取。固定种子不自动消除线程、平台、拓扑与缓存差异。
- 区分创作期插件与渲染期插件：插件创建的普通 Mesh/Action 可能不再依赖插件，动态 node/handler/外部轨迹仍可能依赖。必须实际重开检查。
- 不能以“Pack Resources 已点击”代替缓存、字体、链接库、轨迹数据、外部脚本和版本的逐项核验。

最小复现测试：同一代表帧分别在顺序播放后、乱序跳帧后、保存关闭重开后求值；比较实际关键几何/属性或容差内画面。历史模拟只在已确认缓存范围内乱序测试。失败则先处理缓存或依赖，不能把有问题的帧散发到渲染队列。

原生依据：[Simulation Nodes](https://docs.blender.org/manual/en/5.1/physics/simulation_nodes.html) 说明烘焙用于非顺序渲染；[Blender 4.3 GN 发布说明](https://developer.blender.org/docs/release_notes/4.3/geometry_nodes/) 记录可打包的 bake。实际操作/API仍查目标版本；缓存跨 Blender 版本不能默认兼容。

## 4. 自动化层只负责调度，不接管科学判断

借鉴 MCP 的通信适配、BlenderProc/BlenderSynth 的模块接口和 Flamenco 的任务依赖：
- 将读取状态、受限修改、核验、保存、渲染分为可观察步骤。每步有输入身份、输出、完成/失败状态。
- Blender 原生数据修改尽量显式指定对象/数据块；必须用 operator 时检查 mode、selection、context 与 `poll()`，避免后台无 UI 时失败。[官方 operators 限制](https://docs.blender.org/api/current/info_gotchas_operators.html)。
- 连接工具能够执行 Python，不表示其理解机理或自动保留场景；生成脚本仍需符合当前改动白名单。
- 采用与现有工具兼容的项目内适配，不把“可续作”改成每次 `init`/清空场景。
- 大批量参数扫描适合流水线；研究汇报的主镜头和物理参数不应随训练数据的 domain randomization 一起随机化。
- 对材质/节点/体数据先检查实际引擎能力。允许改表现时才选经过对照验证的等价实现；冻结任务不能借“兼容”为由自行换引擎、材质或几何。

仅用户任务确实需要且环境允许时采用外部 MCP/插件。检查所选版本的执行面、网络/内容上传和遥测设置；保密项目不得因为示例默认联网而自动上传。沿用现有可用连接，不为了使用新项目更换已验证的执行器。

## 5. 把大型项目的经验缩小到单机工作流

Flamenco、Blender Studio 的有用部分是：冻结输入、资产/镜头边界、任务依赖、重试与状态可追踪。单机短片不需要自动部署管理服务器。

将设备资产、机理动画、展示、语言和输出设置标明数据归属；每轮补丁只操作授权层。试验版、待验收版、冻结交付版分别标记，不能仅靠“final”文件名判断状态。跨镜头共享确有需要时使用链接资产/override，并记录谁能更新源资产。

可按 `版本 × 语言 × 镜头/帧范围 × 输出规格` 建任务；缓存/冻结先于渲染，PNG完整性先于编码，编码先于播放验收。跨语言共享动画和样式，只切文字映射。

多机或多进程仅在用户范围与资源允许时启用；每个任务写独立输出，检查 Blender/插件版本、依赖与代表帧等价。异构机器的高光/随机结果可能有细差，需实测。不能为了使用农场改引擎、自动上传未授权资产或牺牲已有验收标准。

## 6. 外部素材服务于视觉，不代替科研结构

从 Poly Haven 借鉴资产 ID、来源、贴图分辨率、纹理复用与相对路径管理。简单摄影棚背景、金属粗糙度参考可复用；关键喷嘴、接触几何、晶体或实验装置以研究依据为准。

分别记录代码、素材、数据和在线 API 的许可/使用条件；开源插件不自动授予第三方模型或数据权利。复制/改编源码时保留适用许可证与归属；只借鉴思路时记录来源，不把上游项目整体混入 skill。

需要外部组件时填写[组件采用记录](../assets/EXTERNAL_COMPONENT_RECORD.md)。记录既用于可复现，也用于下一次替换或移除依赖。
