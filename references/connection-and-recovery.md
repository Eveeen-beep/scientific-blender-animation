# Blender 连接、初次落地与恢复

## 1. 先读现场，后选接入方式

首次任务：动态确认项目目录、Blender 可执行程序、版本、已有文件及需要的输出。
恢复任务：先读当前 `CODEX_HANDOFF.md`，列出相关最新工程、补丁、检查图、日志和渲染进程。
文件名的最大版本号不自动等于可靠基线：检查大小、时间、实际能否打开、上次是否写完和最新授权。
存在同名版本时用完整路径/哈希区分。磁盘与handoff冲突时先只读核对，再修正记录。

最小环境自检：当前目录 → 指定目录可读 → 现有工程存在或已确认的新建空白场景 → 自有临时文件写/读/删 → Blender版本。
首次新建尚无.blend时，以指定的新场景身份完成握手，记录未保存状态；不把没有旧工程视为故障。
临时文件用随机唯一名，以独占创建避免覆盖用户已有文件；只删除刚创建的临时文件。
不要扫描整个系统盘；先查项目、PATH和已知安装目录。原工作目录或旧路径仅作检索线索。

## 2. 接入路线：按可用能力选，不能虚构“已连接”

| 路线 | 适用场景 | 必须取得的证据 |
|---|---|---|
| 已配置 Blender 连接器/MCP | 需要控制正在打开的应用，且工具确实存在 | 实际调用返回目标文件、版本、当前帧、对象列表 |
| Blender 自带 Python `bpy` | 稳定的场景修改、审计、批量输出 | Blender 内执行成功、目标 .blend 路径及报告 |
| 可见 GUI + 受控脚本 | 初始建模/需要用户看到窗口、直接检查界面 | 真实窗口和 .blend 状态；不能用后台截图冒充UI |
| 后台 CLI | 文件核验、可恢复渲染、无人值守脚本 | 可执行版本、进程/日志、输出文件和退出状态 |
| UI 自动化 | 没有适当API或必须点选的界面操作 | 读取当前UI状态，再操作；适用时读取计算机操作skill |

连接器不是必需前提。`import bpy` 通常要在 Blender Python 中运行，普通Python没有它不代表项目损坏。
若必须安装或启用新连接服务，先检查本地插件说明和当前官方文档；仅配置请求所需项，不开公网控制端口、不禁用全局安全功能。
不要把历史本地 socket/轮询补救程序变成所有项目默认依赖。

**只读握手必须能说清：**
`Blender版本 + 实际文件全路径 + 当前Scene/Camera/帧 + frame range/fps + 对象摘要 + 读写模式`。
拿到进程PID或打印“hello”不足以确认连接到用户要的工程。

## 3. 随skill提供的只读检查脚本

在发现本机路径后，用等效命令。PowerShell中的变量只作例示，不预设安装位置：

```powershell
& $blenderExe --background --disable-autoexec $blendPath --python-exit-code 1 --python $inspector -- --output $newReport
```

`$inspector` 指向本skill的 `scripts/inspect_blend.py`；报告必须是新的 `.json` 文件。
命令按顺序处理，先载入工程再运行检查脚本。脚本不会保存 .blend 或开始渲染。
它报告：单位、时间轴、实际输出分辨率、Camera、材质/对象数、局部/世界变换、约束、修改器、Action/Driver入口、依赖和输出路径。

**注意驱动：** `--disable-autoexec` 可能禁用依赖Python的驱动/处理器。因此这个模式适合库存与引用检查，不能仅凭其求值结果宣称动画通过。
对于用户自己的可信工程，检查其Driver/handlers/内嵌文本来源后，用项目已有且获授权的执行设置做真正动画核验；不要为了“让它动”盲目开启未知脚本。
在打开的GUI里有未保存修改时，后台读取磁盘不能替代GUI当前状态；先辨明是否需要保存checkpoint，禁止直接关窗/重新打开导致未保存内容丢失。

## 4. 建模入口与补丁入口分开

新项目初始脚本可创建基础场景，但只在指定的新文件/空白场景中运行。
续作脚本应声明预期源工程/对象、改动白名单、输出新版本及验证结果。出现对象不符时停止该补丁，不清空重建。
能使用原生关键帧、Driver、Shape Key、GN的，应把状态存入.blend；若必须依赖运行时Python/缓存，写明重开文件的加载与执行条件，验证重开后仍能工作。
脚本必须另存到项目scripts，不能只留在对话或Text Editor。后台编码用独立工程/进程上下文，不能把建模Scene切成VSE后保存覆盖模型。

## 5. 恢复先判断“哪一步没完成”

1. 只读核对最新文件与已完成报告；检查活动Blender及其命令行、输出日志、最近帧时间。
2. 若已有对应任务运行且有进展，继续观察，避免并发第二实例。不要只凭PID存在推定正常；也不要为查不到命令行就杀掉进程。
3. 已实现且保存：不重跑构建。已渲染：先验证，不重渲。已有视频：先读metadata/报告，不重编码。
4. 只补缺失环节，长任务前更新handoff；渲染恢复详见 `render-and-delivery.md`。

若连最小只读命令都因宿主执行器无法启动而失败：保留原始错误，停止循环尝试，报告当前目录、最后成功步骤、是否实际保存、需要宿主重启/恢复的事实。
不要把执行器错误当作Blender文件损坏，也不要自行回退另一盘或重迁移。
若仅日志路径失败，尝试在已授权项目子目录写诊断；不因为附属日志失败重做已完成场景。
